* 需和[[v1.1_spi_sender]]配合使用
###  概述
* 一个ESP32的SPI（Serial Peripheral Interface）从设备（也称为SPI接收器或SPI slave）的实现。它与SPI主设备（也称为SPI发送器或SPI master）一起工作，以**全双工**方式传输数据。这意味着，当主设备在MOSI（Master Out Slave In）引脚上放置数据时，从设备在MISO（Master In Slave Out）引脚上放置自己的数据。
* 定义引脚和主机 
* **回调函数**：定义了两个回调函数，`my_post_setup_cb`和`my_post_trans_cb`。这两个函数分别在事务排队并准备好由主设备接收时，以及在发送/接收事务后调用。这些函数用于控制握手线（handshake line）的电平。
* app_main：配置了SPI总线，SPI从设备接口，以及握手线。然后，初始化了SPI从设备接口。
* **数据传输**：在无限循环中，设置了一个128字节的事务以发送/接收。使用`spi_slave_transmit`函数，SPI从设备接口可以发送/接收到sendbuf和recvbuf。这个函数不会返回，直到主设备完成了传输。
### 回调函数
#### my_post_setup_cb
* 调用时机：数据传输之前
* 在SPI从设备已经准备好一个事务并且准备好被主设备接收时被调用。
* 告诉SPI主设备，从设备已经准备好了数据并且可以开始传输。
* 设置握手线为高电平实现。
```c++
// Called after a transaction is queued and ready for pickup by master. We use this to set the handshake line high.
void my_post_setup_cb(spi_slave_transaction_t *trans)
{
    gpio_set_level(GPIO_HANDSHAKE, 1);
}
```

#### my_post_ trans_cb
* 调用时机：数据传输之后
* 在SPI从设备已经完成了一个事务的发送/接收后被调用。
* 告诉SPI主设备，从设备已经完成了数据的接收。
* 设置握手线为低电平实现。
```c++
// Called after transaction is sent/received. We use this to set the handshake line low.
void my_post_trans_cb(spi_slave_transaction_t *trans)
{
    gpio_set_level(GPIO_HANDSHAKE, 0);
}
```

### SPI_Configuration_Initialize
#### Configuration for the SPI bus
*  SPI通信的基础配置，包括MOSI（主出从入）引脚，MISO（主入从出）引脚，和SCLK（时钟）引脚。
```c++
 spi_bus_config_t buscfg = {
        .mosi_io_num = GPIO_MOSI,
        .miso_io_num = GPIO_MISO,
        .sclk_io_num = GPIO_SCLK,
        .quadwp_io_num = -1,
        .quadhd_io_num = -1,
    };
```

#### Configuration for the SPI slave interface
* SPI从机接口配置（SPI Slave Interface Configuration)：主要包括SPI模式（mode），CS（片选）引脚，队列大小（queue size），以及两个回调函数（post_setup_cb和post_trans_cb）。
```c++
spi_slave_interface_config_t slvcfg = {
        .mode = 0,
        .spics_io_num = GPIO_CS,
        .queue_size = 3,
        .flags = 0,
        .post_setup_cb = my_post_setup_cb,
        .post_trans_cb = my_post_trans_cb
        
};
```
#### Configuration for the hanshake line
* 握手线配置（Handshake Line Configuration）：设置握手线（handshake line）的GPIO模式为输出模式。
```c++
    // Configuration for the handshake line
    gpio_config_t io_conf = {
        .intr_type = GPIO_INTR_DISABLE,
        .mode = GPIO_MODE_OUTPUT,
        .pin_bit_mask = (1 << GPIO_HANDSHAKE)
    };
	// Configure handshake line as output
    gpio_config(&io_conf);
```

####  Enable pull-ups on SPI lines
* don't detect rogue pulses when no master is connected.
```c++
	gpio_set_pull_mode(GPIO_MOSI, GPIO_PULLUP_ONLY);
    gpio_set_pull_mode(GPIO_SCLK, GPIO_PULLUP_ONLY);
    gpio_set_pull_mode(GPIO_CS, GPIO_PULLUP_ONLY);
```
#### Initialize SPI slave interface
* 调用`spi_slave_initialize`函数，将上述的总线配置和从机接口配置应用到SPI从机上。
```c++
 ret = spi_slave_initialize(RCV_HOST, &buscfg, &slvcfg, SPI_DMA_CH_AUTO);
 assert(ret == ESP_OK);
```

#### SPI Transaction Configuration
* SPI交易配置（SPI Transaction Configuration）：设置SPI交易的长度，发送缓冲区，接收缓冲区等。
```c++
	WORD_ALIGNED_ATTR char sendbuf[129] = "";
    WORD_ALIGNED_ATTR char recvbuf[129] = "";
    memset(recvbuf, 0, 33);
    spi_slave_transaction_t t;
    memset(&t, 0, sizeof(t));
```

### while(1)

#### debugging and error detection.
* Clear the receive buffer by setting each byte to 0xA5. This is done before receiving new SPI data.
* If the SPI receive operation is not successful, or the received data does not completely fill the buffer,
* we can detect this issue by checking if there are still 0xA5s in the buffer.
* This technique of filling memory with a specific value (like 0xA5 or 0xFF) is often used for debugging and error detection.
```c++
memset(recvbuf, 0xA5, 129);
```
#### spi_slave_transmit(RCV_HOST, &t, portMAX_DELAY)
* `spi_slave_transmit`函数是一个阻塞函数，它会等待直到SPI主机完成一次传输。这意味着当这个函数返回时，数据已经被发送并且可能已经接收到了新的数据。
* 因此，如果这个函数返回了一个错误代码，那么可能是在数据传输过程中出现了问题。然而，在这段代码中，作者并没有检查这个函数的返回值，可能是因为他们假设在正常的硬件和软件条件下，这个函数不会失败。
```c++
ret = spi_slave_transmit(RCV_HOST, &t, portMAX_DELAY);
        if (ret != ESP_OK)
        {
            // Handle the error
            ESP_LOGE("SPI_SLAVE", "spi_slave_transmit failed with error code: %d", ret);
        }

        // spi_slave_transmit does not return until the master has done a transmission, so by here we have sent our data  
```
#### code
```c++
	while (1)
    {
        // Clear the receive buffer by setting each byte to 0xA5. This is done before receiving new SPI data.
        memset(recvbuf, 0xA5, 129);
        sprintf(sendbuf, "This is the receiver, sending data for transmission number %04d.", n);

        // Set up a transaction of 128 bytes to send/receive
        t.length = 128 * 8;
        t.tx_buffer = sendbuf;
        t.rx_buffer = recvbuf;
        /* This call enables the SPI slave interface to send/receive to the sendbuf and recvbuf. The transaction is
        initialized by the SPI master, however, so it will not actually happen until the master starts a hardware transaction
        by pulling CS low and pulsing the clock etc. In this specific example, we use the handshake line, pulled up by the
        .post_setup_cb callback that is called as soon as a transaction is ready, to let the master know it is free to transfer
        data.
        */
        ret = spi_slave_transmit(RCV_HOST, &t, portMAX_DELAY);
        if (ret != ESP_OK)
        {
            // Handle the error
            ESP_LOGE("SPI_SLAVE", "spi_slave_transmit failed with error code: %d", ret);
        }

        // spi_slave_transmit does not return until the master has done a transmission, so by here we have sent our data and
        // received data from the master. Print it.
        printf("Received: %s\n", recvbuf);
        n++;
    }
```
