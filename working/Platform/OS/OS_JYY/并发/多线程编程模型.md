## 互斥

###  阻止并发 (并行) 的发生

多处理器和并发执行推翻了顺序执行的基本假设

#### 状态机视角的互斥

- 临界区同时发生时，依旧满足执行的原子性
- 可以把多按此状态迁移理解为“一次大状态迁移”

#### 在操作系统内核中借助关中断机制实现互斥

- 中断是操作系统管理的。在应用程序中，关闭中断是不能容忍的，但是在操作系统内核的实现中，关闭中断是一个常见的操作。

#### 单处理器可以，多处理器系统不可行

- 每个处理器有独立的寄存器组
- 中断是每个处理器内部状态

### 计算机系统 = 状态机

- 处理器随时可以被中断
- 中断时可能试图获取自旋锁
- 互斥 = 关中断 + 自旋
- 关中断只能实现本处理器的 Stop the World
- 自旋才能实现和其他处理器的 “Stop the World”

### 自旋锁使用场景

- 操作系统内核的并发数据结构（短临界区）
- 许多操作系统内核对象具有“read-mostly” 特点

## 同步

在解决同步问题时，关键在于理解 **“同步成功”** 的条件是什么。然后各个线程在条件不满足时**等待**，直到条件满足方可继续。这个思路自然地引出了 “条件变量” 这一同步机制。

分解任务为有向无环图
为每个节点设置一个条件变量
对于每个节点来说，在节点执行之前确保指向该节点的前向节点都实现。

## 信号量

信号量是互斥锁的一种拓展

```c
void P(sem_t *sem) {
    // P - prolaag
    //     try + decrease/down/wait/acquire
    atomic {
        wait_until(sem->count > 0) {
            sem->count--;
        }
    }
}

void V(sem_t *sem) {
    // V - verhoog
    //     increase/up/post/signal/release
    atomic {
        sem->count++;
    }
}
```
## 信号量与条件变量
### 信号量
- 互斥锁的自然推广
- 干净、优雅：没有条件变量的 “自旋”
### 条件变量
- 万能：适用于任何同步条件
- 不太好用：代码总感觉不太干净

数值型资源不总是能够很好地代表同步条件--在处理哲学家就餐这类问题时，条件变量处理起来更加顺手，并且其自旋锁造成的性能损失也可忽略不计。
